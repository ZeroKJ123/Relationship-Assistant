# Home-Assist

Приложение для пары с просьбами, совместными планами и благодарностями. Доступны аккаунты и восстановление резервным кодом, пары, приглашения, недельные договорённости, просьбы и встречные условия. Работают отдельная проверка выполнения, личный журнал сердечек, награды, штрафы и лимиты «Очень хочу». Добавлены административные версии правил, резерв цены услуг и стартовые каталоги. Добавлены кухня, ручной виш-лист и денежные просьбы с отдельным подтверждением получения. Добавлены личные друзья, гостевые визиты, свидания и совместные мероприятия. Добавлены настроение с историей за 30 дней и разовые напоминания. Реализованы вход, привязка и подтверждаемые действия Telegram; для живого подключения нужны настройки бота и публичный HTTPS-адрес. Главная показывает текущую пару, настроение, сердечки и ближайшие дела; кухня и панель условий адаптированы для телефона. Дела разделены по статусам и подтверждаются в два этапа; виш-лист показывает состояния подарков и поддерживает предпросмотр фото. Подготовлено использование через браузер в локальной сети; установка PWA и живой Telegram требуют HTTPS и отдельной настройки.

PHP 8.4, Laravel 13, MariaDB 11.4, Blade, Tailwind CSS 4 и Vite 8. Локальная среда запускается через Laravel Sail.

## Адреса

- Приложение при стандартной установке: http://localhost:8086
- Для использования с телефона: IP и порт ноутбука из `APP_URL`; настройка описана в [эксплуатации](docs/operations.md).
- MariaDB с компьютера: `127.0.0.1:33070`
- Vite при разработке: http://localhost:5176

Пример установки использует базу `homeassist`, пользователя `sail` и локальный пароль `password`; для постоянного использования задайте собственный пароль в `.env`. Из контейнера Laravel база доступна по `mariadb:3306`. По умолчанию порты доступны только на этом компьютере. `APP_BIND_ADDRESS=0.0.0.0` открывает только порт приложения в локальную сеть.

## Обычный запуск

Запустите Docker Desktop, затем из папки проекта:

```sh
./vendor/bin/sail up -d
```

Собранный интерфейс уже доступен без запуска Vite. Для автоматического обновления интерфейса во время разработки:

```sh
./vendor/bin/sail npm run dev
```

Vite работает до завершения команды. После завершения браузер снова использует собранные ресурсы. После изменений пересоберите их:

```sh
./vendor/bin/sail npm run build
```

Остановить только этот проект, сохранив базу:

```sh
./vendor/bin/sail stop
```

## Первая установка на другом компьютере

Нужны Docker Desktop и Composer с PHP 8.4+ для установки зависимостей.

```sh
composer install
cp .env.example .env
php artisan key:generate
./vendor/bin/sail up -d
./vendor/bin/sail artisan migrate
./vendor/bin/sail artisan db:seed --class=EconomySettingsSeeder
./vendor/bin/sail artisan db:seed --class=CatalogSeeder
./vendor/bin/sail npm ci
./vendor/bin/sail npm run build
```

В Linux задайте `WWWUSER` и `WWWGROUP` в `.env` по результатам `id -u` и `id -g`. При необходимости измените `APP_PORT`, `APP_URL`, `FORWARD_DB_PORT` и `VITE_PORT` перед запуском. Пример `.env.example` не содержит ключ приложения: при первой установке он генерируется отдельно.

## Работа с проектом

- Маршруты страниц: `routes/web.php`.
- Шаблоны: `resources/views/`.
- Стили и JavaScript: `resources/css/app.css`, `resources/js/app.js`.
- Модели: `app/Models/`.
- Изменения схемы базы: `database/migrations/`.
- Начальные миграции создают пользователей, сессии, кэш и очередь заданий. Новые миграции расширяют профиль и создают таблицу Telegram-идентификаторов; вход, привязка и быстрые кнопки бота описаны в документации Telegram. Миграция пар добавляет couples, couple_members и couple_invitations; описание применения и отката — в документации пар.
- По умолчанию сессии, кэш и очередь используют MariaDB. Почта записывается в локальный журнал. Для очереди Telegram и расписания нужны отдельные процессы из [инструкции Telegram](docs/telegram-and-scheduling.md).
- Миграции экономики, резервов и каталогов и их начальное заполнение описаны в [экономике и каталогах](docs/economy-and-catalogs.md).
- Миграция друзей и приглашений описана в [друзьях, гостях и свиданиях](docs/friends-guests-dates.md).
- Для проверки просрочек после применения миграций нужен scheduler; запуск и ограничения описаны в [делах и сердечках](docs/hearts-and-duties.md).

```sh
./vendor/bin/sail composer check
./vendor/bin/sail logs
```

Тесты принудительно используют SQLite в памяти; защитная проверка запрещает постоянную базу, URL подключения и кешированную конфигурацию. Отдельные тесты гонок и ограничений пар работают в одноразовой MariaDB; см. документацию разработки.

## Изоляция

Имя Compose-проекта в примере — `homeassist`. У него свои контейнеры, сеть, образ приложения `sail-starter-8.4/app` и том `homeassist_sail-mariadb`. Окружение работает в фоне и автоматически запускается после перезапуска Docker, если вы не остановили его вручную. Данные сохраняются в отдельном Docker-томе.

`work/` содержит временные файлы установки и не нужен для работы приложения. Зависимости зафиксированы в `composer.lock` и `package-lock.json`. Файл `.env` исключён из Git. Эта конфигурация предназначена для локальной разработки.
