# Разработка и проверки

## Проверка изменений

PHP 8.4 и зависимости из `composer.lock` обязательны. Node.js 22+ используется для сборки.

```sh
composer install
npm ci
composer check
npm run build
```

`composer check` запускает Pint в режиме проверки, PHPStan/Larastan уровня 8 и Pest. Правила находятся в `pint.json`, `phpstan.neon` и [CodeStyle](../CodeStyle.md). Обычные PHP-файлы требуют strict_types; Blade и автоматически созданный кеш исключены. Pint использует `no_useless_else`; предпочтение ранних выходов дополнительно проверяется при саморевью. Для исправления форматирования: `vendor/bin/pint`.

GitHub Actions запускает те же проверки и сборку без деплоя. Перед push проверяется весь отправляемый диапазон; ошибка любой обязательной проверки запрещает отправку.

## Изолированное тестирование

`phpunit.xml` принудительно задаёт testing, SQLite `:memory:`, тестовый ключ шифрования, сессии/кеш в памяти и синхронную очередь. Этот ключ служит только тестам. Кеш конфигурации, постоянная база или URL подключения приводят к отказу до подготовки данных. В тестовом приложении остаётся только SQLite-подключение; неожиданные HTTP-запросы блокируются.

```sh
php artisan test --compact
php artisan test --compact --filter=TestEnvironment
```

Сценарии используют Pest `it()`. Тесты изоляции проверяют отказ для постоянной базы, нетестового окружения и URL подключения. Сценарии интерфейса проверяют русский язык, экранирование личных данных и доступные поля. Рабочая MariaDB не используется. Для пар, приглашений и договорённостей добавлена отдельная MariaDB-среда: SQLite не подтверждает корректность блокировок и гонок.

## Конкурентные операции в MariaDB

Используйте отдельный одноразовый контейнер, без рабочих томов:

```sh
docker run --rm -d --name homeassist-couples-test --tmpfs /var/lib/mysql:rw,size=512m -p 127.0.0.1:33071:3306 -e MARIADB_DATABASE=homeassist_couples_testing -e MARIADB_USER=homeassist_test -e MARIADB_PASSWORD=test_only_password -e MARIADB_RANDOM_ROOT_PASSWORD=yes mariadb:11.4
docker exec homeassist-couples-test healthcheck.sh --connect --innodb_initialized
vendor/bin/pest --configuration=phpunit.mariadb.xml
docker stop homeassist-couples-test
```

Ключ и пароль здесь предназначены только для одноразовой тестовой базы. Проверка окружения до миграций требует testing, отсутствия кеша конфигурации и DB_URL, хост 127.0.0.1, порт 33071, имя homeassist_couples_testing и пользователя homeassist_test. Другие подключения удаляются из тестового приложения. Эти тесты пересоздают только выделенную тестовую схему; не подключайте к этому контейнеру рабочие данные. Общий протокол ConcurrentOperations используется приглашениями и договорённостями. PHP-процессы синхронизируются стартовым барьером; адаптация вывода Pao отключена только в дочернем протоколе, проверки остаются включены.

## Дела и журнал сердечек

Сценарии `DutiesTest` и `HeartsTest` проверяют отдельные обязанности, оба подтверждения, повторные операции, роли, снимки тарифов, отрицательный баланс, фактические суммы и лимиты. `DutyConcurrencyTest` и `HeartConcurrencyTest` запускают независимые процессы MariaDB для гонок отметок/проверок, балансов, стартового бонуса, наград, благодарностей и недельной квоты. Тестовые фабрики новых моделей сохраняют согласованные связи и баланс. Рабочие миграции не выполняются этими проверками.

Команды `duties:check-overdue` и `hearts:check-balances` описаны вместе с расписанием и ограничениями в [делах и сердечках](hearts-and-duties.md). Просрочки требуют работающего scheduler в окружении с применёнными миграциями; сверка журнала сообщает ошибку без молчаливого исправления.

## Настройки, резерв и каталоги

`EconomySettingsTest`, `ServicePaymentsTest` и `CatalogsTest` проверяют административные права, версии и конфликты, согласование цены, защищённый резерв, списание только после проверки, взаимную отмену, снимки каталогов, приватность и повтор отправки. `EconomyPaymentConcurrencyTest` проверяет независимые процессы: конкурирующие версии настроек, два заказа на один баланс, штраф одновременно со списанием, отмену одновременно с проверкой. Все проверки используют те же защищённые SQLite/MariaDB-среды.

```sh
php artisan test --compact tests/Feature/EconomySettingsTest.php tests/Feature/ServicePaymentsTest.php tests/Feature/CatalogsTest.php
vendor/bin/pest --configuration=phpunit.mariadb.xml tests/Integration/EconomyPaymentConcurrencyTest.php
```

Начальное заполнение, границы реализации и обратный порядок миграций описаны в [экономике и каталогах](economy-and-catalogs.md).

## Laravel Boost

Boost установлен как dev-зависимость; инструкции обновляются командой `APP_ENV=local php artisan boost:install --guidelines --no-interaction`. После обновления перечитайте AGENTS.md и CodeStyle.md. CodeStyle имеет приоритет над общими указаниями Boost, включая обязательный Pint --test. Пользовательские правила Git и проверки перед push сохранены.

Для денежных вычислений используется `brick/math`: суммы сохраняются точно; приложение не выполняет банковские переводы. Логи регулируются `LOG_LEVEL`, содержат технический этап и причину отказа без личного текста и секретов.

## Проверки и размещение PWA

`npm run test:pwa` запускает Node.js-тесты без сторонних библиотек: защита личных данных, отсутствие offline-действий, кэширование публичных ресурсов, границы/обновление кэша, обработка сбоя хранилища, ручной запрос установки и возврат авторизованной страницы. Команда включена в GitHub Quality после сборки. `PwaScreensTest` проверяет приватные заголовки HTML, манифест и размеры иконок. В разработке через Vite worker не регистрируется; проверять нужно собранное приложение.

Для размещения нужен HTTPS и сайт в корне домена; локальный localhost подходит только для разработки. `/sw.js` должен иметь JavaScript MIME, `/manifest.webmanifest` — `application/manifest+json`; оба отдавать с `Cache-Control: no-cache`. Публичная Apache-конфигурация добавляет заголовок при наличии mod_headers и MIME при mod_mime. Для Nginx или другой целевой среды эти правила нужно настроить отдельно после подтверждения окружения; proxy/CDN не должен кэшировать личный HTML/JSON. Никогда не назначайте immutable файлу worker. У ресурсов `/build/assets/` имена содержат хеш; новая сборка создаёт новые ключи. При изменении worker-политики меняйте CACHE_NAME, при изменении offline-экрана/иконок — их версионированные пути. Миграции и новые зависимости для PWA не нужны.

До выпуска: открыть публичный HTTPS-сайт в реальном Chrome Android и Safari iOS, установить из профиля/меню, проверить запуск в standalone и safe-area, выключить сеть, убедиться в отсутствии личных данных на offline-экране, восстановить сеть, затем выйти и проверить возврат назад. Проверить обновление после новой сборки без потери незавершённого ввода. Текущий согласованный способ использования — браузер по HTTP в локальной сети. Приёмка установки PWA на реальных устройствах остаётся отдельной проверкой для будущего HTTPS-размещения; локальные тесты её не заменяют.

## Проверка процессов

`RuntimeProcessesTest` проводит напоминание через настоящий обработчик database-очереди с поддельным Telegram API: повтор сканирования не отправляет второе сообщение; отключение бота сохраняет ожидание, после включения диспетчер восстанавливает доставку. База — SQLite в памяти, внешние HTTP-запросы запрещены. Оба PHPUnit-конфига и среда дочерних MariaDB-процессов принудительно отключают Telegram и очищают токен, имя и секрет настоящего бота. Только сценарии Telegram включают транспорт с поддельным токеном и `Http::fake`.
