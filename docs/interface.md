# Основа интерфейса

Страница `/` использует сиреневую, жёлтую и розовую палитру. Гость видит знакомство с приложением, вошедший пользователь — главную с данными своего аккаунта и текущей пары. Имена, баланс, настроение и даты не подменяются демонстрационными значениями.

## Компоненты

| Компонент | Назначение |
| --- | --- |
| `card` | Карточки с общей палитрой |
| `button` | Основное, спокойное и опасное действие |
| `field` | Связанные label, поле и ошибка |
| `avatar` | Фото или безопасная первая буква имени |
| `status` | Текстовый статус |
| `dialog` | Модальное окно в виде нижней панели |
| `confirmation` | Подтверждение отправки формы без повторного клика |
| `tabs` | Доступные вкладки |
| `bottom-navigation` | Главная, просьбы текущей пары и профиль |
| `dish-card` | Фото, состав, продукты, сердечки и доступное действие |
| `condition-form` | Общее содержание формы встречного условия |

Компоненты находятся в `resources/views/components`, общий каркас в `resources/views/layouts/app.blade.php`. CSS задаёт общие токены, размеры зон нажатия и видимый фокус. Локальный Nunito с кириллицей поставляется с SIL Open Font License в `public/fonts/OFL.txt`.

`resources/js/modules/dialogs.js` открывает/закрывает панели, возвращает фокус и поддерживает стрелки, Home и End во вкладках. `confirmation` требует существующую форму по ID, проверяет её валидность и блокирует повторное нажатие; сервер всё равно обязан проверять права и идемпотентность. Без JavaScript основное содержание доступно, вместо модальной подсказки показывается текст.

## Ручная проверка

После `npm run build` откройте сайт по адресу из README.

1. На ширине 320–390 px убедитесь, что текст и нижняя навигация помещаются без горизонтальной прокрутки.
2. Нажмите «Как это будет работать»: панель открывается, Tab остаётся внутри неё, Escape закрывает и возвращает фокус кнопке.
3. Во вкладках используйте стрелки, Home и End: выбранная вкладка и её содержание должны совпадать.
4. Включите уменьшение анимаций: переходы отключены.
5. Отключите JavaScript: сведения о регистрации остаются доступными.

Регистрация, вход и профиль уже доступны; пары и приглашения также работают; общие текстовые просьбы и условия доступны. Вход и подтверждаемые действия Telegram реализованы; живое подключение требует настройки бота и публичного HTTPS-адреса. Банковские переводы и интеграция с живым Home Assistant не выполняются.

## Главная

Главная показывает имя пользователя, партнёра, длительность отношений в календарных днях по зоне пары, последние оценки настроения, общий баланс, резерв и свободные сердечки. Четыре плитки ведут к кухне партнёра, новой просьбе, свиданию и личному виш-листу. Для отсутствующей пары предлагается создание или приглашение; личные каталоги доступны сразу. До согласования первого лимита показан переход к договорённости.

«Мои дела» показывает до трёх ближайших незавершённых обязанностей пользователя, включая ожидание проверки и спор. «Все» открывает полный список. Отдельная карточка показывает последнюю ожидающую ответа входящую просьбу. Данные прежней пары на главную не попадают. Минус отображается со знаком, обычная бесплатная еда остаётся доступной.

`DashboardController` использует `DashboardData` и типизированный `DashboardViewModel`. `WalletSnapshot` читает баланс и резерв согласованно под блокировкой. При ошибке загрузки возвращается страница 503 с кнопкой повтора и безопасным номером обращения. Диагностика содержит только технические ID, время загрузки и количество дел.

Проверяйте 360/390/430 px, длинные имена, отсутствие партнёра, несогласованный лимит, пустые дела, новые просьбы и отрицательный баланс. Нижняя навигация ведёт на реальные страницы. JavaScript показывает состояние перехода и снимает его при возврате назад.

## Экраны пары

«Мои пары» показывает текущую пару и историю с пагинацией. Приглашение требует подтверждения получателя, завершение пары — отдельного экрана подтверждения. Формы работают без JavaScript; JavaScript блокирует повторное нажатие во время отправки. Статусы сопровождаются текстом. В профиле доступны переходы к парам и продолжение принятия ссылки после регистрации.

Проверяйте длинные имена, пустую историю, ссылку на узком экране, отменённые/просроченные приглашения и подтверждения с клавиатуры. Подробнее: [пары и приглашения](couples.md).

## Договорённости

Экран лимита показывает ответы обоих партнёров, предложенный компромисс, число согласий и историю версий с пагинацией. Каждый вариант принимается явным подтверждением; можно отклонить или предложить другое число. Поля личного ответа и нового предложения имеют разные ID и связанные label. Действующее правило остаётся видимым при обсуждении замены. Для ожидающей/завершённой пары экран доступен только для чтения.

## Просьбы и условия

Список, создание и детали доступны из страницы пары. Срок вводится в часовом поясе пары; форма условия показывает отдельный срок. Получатель отвечает с явным подтверждением, автор отдельно принимает/отклоняет текущий вариант условия. История сохраняется. Новые операции закрыты после завершения пары.

Проверяйте формы с JavaScript и без него, перенос длинных имён на 320 px, связанные подписи, возврат ошибок и повторную отправку. Скрипт блокировки сохраняет имя и значение выбранной кнопки в скрытом поле перед отключением кнопок, чтобы согласие/отказ не терялись. После возврата назад временные поля удаляются и кнопки вновь доступны. Подробности: [просьбы и условия](requests.md).

Кнопка «С условием» открывает нижнюю панель с выбором действия, поцелуев, своего варианта, денег, подарка или суши. Ненужные поля скрыты и не отправляются; смена вида очищает прежнюю сумму, желание и размер. Валюта сохраняется как предпочтение и отправляется только для денег. Автор всё равно принимает условие отдельно. Escape закрывает панель и возвращает фокус; содержимое прокручивается внутри неё. При серверной ошибке панель открывается с прежним вводом. Без JavaScript отображаются обычная форма и все подписи; выбирайте совместимые поля вручную.

## Дела и сердечки

Из карточки пары доступны «Наши дела» и «Мои сердечки». У услуги и принятого встречного условия отдельные карточки, исполнители и сроки. Исполнитель явно подтверждает отметку, партнёр отдельно проверяет результат; показываются обе серверные даты и история ответов. Личный журнал показывает фактическую сумму, причину ручной операции и баланс после неё. Форма благодарности/списания требует причины и подтверждения; получатель определяется сервером.

Проверяйте последовательность обоих участников, запрет самопроверки, ожидание результата, мобильную ширину 320 px и длинные имена. Формы работают без JavaScript. Повтор отправки не дублирует начисление. Подробнее: [дела и сердечки](hearts-and-duties.md).

## Экономика, резерв и каталоги

Администратор открывает «Экономика сердечек» из профиля, изменяет правила и явно подтверждает сохранение. История показывает версии, время UTC и технический номер администратора. Обычный участник не имеет доступа к редактору.

В «Моих сердечках» показаны общий баланс, свободная часть и резерв. Проверьте создание платной услуги → согласие → отметка → проверка, а также предложение отмены → согласие второго участника → освобождение резерва. У автора предложения отмены отображается ожидание партнёра.

«Каталоги» доступны из пары. Шаблон применяется отдельной GET-формой и работает без JavaScript; после выбора нужно уточнить срок. Личный способ видит его владелец, отправленный снимок условия — партнёр. Для суши требуется размер, который не определяет цену.

Новые страницы проверены при ширине 320 px с длинным именем, без горизонтальной прокрутки и повторяющихся ID; шаблоны и сохранение правил проверены без JavaScript. См. [экономику и каталоги](economy-and-catalogs.md).

## Кухня и редактор

Кухня показывает собственные блюда или каталог действующего партнёра, фильтры по виду и две разные цены: примерные расходы на продукты в валюте карточки и стоимость заказа в сердечках. При минусе особые блюда недоступны, включая бесплатные особые; при нехватке свободного остатка у платного блюда показана причина. Сервер повторно проверяет правила при отправке, поэтому устаревшая страница не даёт права на заказ.

При выборе обычного блюда редактор устанавливает 0 сердечек. Фото можно просмотреть до сохранения; неподходящий формат, размер или ошибка чтения показаны рядом с полем. Серверная проверка и закрытая выдача сохраняются. Недоступное изображение в карточке заменяется подписью. Подробности: [кухня, желания и деньги](dishes-wishlist-money.md).

## Обязанности и виш-лист

Дела разделены на активные, ожидающие проверки, завершённые и все. Подтверждение ответа открывается отдельной нижней панелью; проверяющий партнёр проходит свою стадию. Возможная награда не показывается как новое обещание для уже завершённого дела. Подробнее: [дела и сердечки](hearts-and-duties.md).

Карточка желания использует фото слева и подробности справа, а при ширине до 360 px — одну колонку. Общий модуль фотографий обслуживает кухню и желания: предпросмотр, ошибки файла и недоступные фото в каталоге. Владелец может редактировать и архивировать свободное желание; партнёр просматривает его. Добавление, просмотр и архив работают без JavaScript. Подробнее: [кухня, желания и деньги](dishes-wishlist-money.md).

## Дополнительные формы и настройки

Профиль разделён на личные данные, валюту, реквизиты и состояние Telegram. Из «Моего пространства» доступны кухня, виш-лист, друзья, сердечки, пары и расписание текущей пары. Экономика видна только администратору. Состояние подключения показано текстом; секретные данные бота не выводятся.

Формы денег, свиданий и напоминаний используют общие поля валюты и многострочного текста, показывают ошибки рядом с полями и часовой пояс пары. Обычные поля сохраняются при ошибке; реквизиты не переносятся во временный ввод, в профиле снова видны ранее сохранённые данные. Отправка блокируется от повторного клика. Подтверждение обязательно и без JavaScript. Денежный запрос не выполняет банковский перевод, а напоминание не считается доставленным по факту сохранения.

Журнал сердечек показывает личный баланс, свободный остаток, резерв и историю. Для ручной благодарности или списания нужно ввести сумму, причину и подтвердить действие. Редактор экономики разделён на баланс, награды, благодарности, списания и штрафы; история версий остаётся доступной. Все дополнительные экраны используют нижнюю навигацию и мобильную типографику.
