# Основа интерфейса

Страница `/` использует сиреневую, жёлтую и розовую палитру. Гость видит знакомство с приложением, вошедший пользователь — главную с данными своего аккаунта и текущей пары. Имена, баланс, настроение и даты не подменяются демонстрационными значениями.

## Компоненты

| Компонент | Назначение |
| --- | --- |
| `card` | Карточки с общей палитрой |
| `button` | Основное, спокойное и опасное действие |
| `field` | Связанные label, поле и ошибка |
| `avatar` | Фото или безопасная первая буква имени |
| `status` | Текстовый статус |
| `dialog` | Модальное окно в виде нижней панели |
| `confirmation` | Подтверждение отправки формы без повторного клика |
| `tabs` | Доступные вкладки |
| `bottom-navigation` | Главная, просьбы текущей пары и профиль |
| `dish-card` | Фото, состав, продукты, сердечки и доступное действие |
| `condition-form` | Общее содержание формы встречного условия |

Компоненты находятся в `resources/views/components`, общий каркас в `resources/views/layouts/app.blade.php`. CSS задаёт общие токены, размеры зон нажатия и видимый фокус. Локальный Nunito с кириллицей поставляется с SIL Open Font License в `public/fonts/OFL.txt`.

`resources/js/modules/dialogs.js` открывает/закрывает панели, возвращает фокус и поддерживает стрелки, Home и End во вкладках. `confirmation` требует существующую форму по ID, проверяет её валидность и блокирует повторное нажатие; сервер всё равно обязан проверять права и идемпотентность. Без JavaScript основное содержание доступно, вместо модальной подсказки показывается текст.

## Ручная проверка

После `npm run build` откройте сайт по адресу из README.

1. На ширине 320–390 px убедитесь, что текст и нижняя навигация помещаются без горизонтальной прокрутки.
2. Нажмите «Как это будет работать»: панель открывается, Tab остаётся внутри неё, Escape закрывает и возвращает фокус кнопке.
3. Во вкладках используйте стрелки, Home и End: выбранная вкладка и её содержание должны совпадать.
4. Включите уменьшение анимаций: переходы отключены.
5. Отключите JavaScript: сведения о регистрации остаются доступными.

Регистрация, вход и профиль уже доступны; пары и приглашения также работают; общие текстовые просьбы и условия доступны. Вход и подтверждаемые действия Telegram реализованы; живое подключение требует настройки бота и публичного HTTPS-адреса. Банковские переводы и интеграция с живым Home Assistant не выполняются.

## Главная

Главная показывает имя пользователя, партнёра, длительность отношений в календарных днях по зоне пары, последние оценки настроения, общий баланс, резерв и свободные сердечки. Четыре плитки ведут к кухне партнёра, новой просьбе, свиданию и личному виш-листу. Для отсутствующей пары предлагается создание или приглашение; личные каталоги доступны сразу. До согласования первого лимита показан переход к договорённости.

«Мои дела» показывает до трёх ближайших незавершённых обязанностей пользователя, включая ожидание проверки и спор. «Все» открывает полный список. Отдельная карточка показывает последнюю ожидающую ответа входящую просьбу. Данные прежней пары на главную не попадают. Минус отображается со знаком, обычная бесплатная еда остаётся доступной.

`DashboardController` использует `DashboardData` и типизированный `DashboardViewModel`. `WalletSnapshot` читает баланс и резерв согласованно под блокировкой. При ошибке загрузки возвращается страница 503 с кнопкой повтора и безопасным номером обращения. Диагностика содержит только технические ID, время загрузки и количество дел.

Проверяйте 360/390/430 px, длинные имена, отсутствие партнёра, несогласованный лимит, пустые дела, новые просьбы и отрицательный баланс. Нижняя навигация ведёт на реальные страницы. JavaScript показывает состояние перехода и снимает его при возврате назад.

## Экраны пары

«Мои пары» показывает текущую пару и историю с пагинацией. Приглашение требует подтверждения получателя, завершение пары — отдельного экрана подтверждения. Формы работают без JavaScript; JavaScript блокирует повторное нажатие во время отправки. Статусы сопровождаются текстом. В профиле доступны переходы к парам и продолжение принятия ссылки после регистрации.

Проверяйте длинные имена, пустую историю, ссылку на узком экране, отменённые/просроченные приглашения и подтверждения с клавиатуры. Подробнее: [пары и приглашения](couples.md).

## Договорённости

Экран лимита показывает ответы обоих партнёров, предложенный компромисс, число согласий и историю версий с пагинацией. Каждый вариант принимается явным подтверждением; можно отклонить или предложить другое число. Поля личного ответа и нового предложения имеют разные ID и связанные label. Действующее правило остаётся видимым при обсуждении замены. Для ожидающей/завершённой пары экран доступен только для чтения.

## Просьбы и условия

Список, создание и детали доступны из страницы пары. Срок вводится в часовом поясе пары; форма условия показывает отдельный срок. Получатель отвечает с явным подтверждением, автор отдельно принимает/отклоняет текущий вариант условия. История сохраняется. Новые операции закрыты после завершения пары.

Проверяйте формы с JavaScript и без него, перенос длинных имён на 320 px, связанные подписи, возврат ошибок и повторную отправку. Скрипт блокировки сохраняет имя и значение выбранной кнопки в скрытом поле перед отключением кнопок, чтобы согласие/отказ не терялись. После возврата назад временные поля удаляются и кнопки вновь доступны. Подробности: [просьбы и условия](requests.md).

Кнопка «С условием» открывает нижнюю панель с выбором действия, поцелуев, своего варианта, денег, подарка или суши. Ненужные поля скрыты и не отправляются; смена вида очищает прежнюю сумму, желание и размер. Валюта сохраняется как предпочтение и отправляется только для денег. Автор всё равно принимает условие отдельно. Escape закрывает панель и возвращает фокус; содержимое прокручивается внутри неё. При серверной ошибке панель открывается с прежним вводом. Без JavaScript отображаются обычная форма и все подписи; выбирайте совместимые поля вручную.

## Дела и сердечки

Из карточки пары доступны «Наши дела» и «Мои сердечки». У услуги и принятого встречного условия отдельные карточки, исполнители и сроки. Исполнитель явно подтверждает отметку, партнёр отдельно проверяет результат; показываются обе серверные даты и история ответов. Личный журнал показывает фактическую сумму, причину ручной операции и баланс после неё. Форма благодарности/списания требует причины и подтверждения; получатель определяется сервером.

Проверяйте последовательность обоих участников, запрет самопроверки, ожидание результата, мобильную ширину 320 px и длинные имена. Формы работают без JavaScript. Повтор отправки не дублирует начисление. Подробнее: [дела и сердечки](hearts-and-duties.md).

## Экономика, резерв и каталоги

Администратор открывает «Экономика сердечек» из профиля, изменяет правила и явно подтверждает сохранение. История показывает версии, время UTC и технический номер администратора. Обычный участник не имеет доступа к редактору.

В «Моих сердечках» показаны общий баланс, свободная часть и резерв. Проверьте создание платной услуги → согласие → отметка → проверка, а также предложение отмены → согласие второго участника → освобождение резерва. У автора предложения отмены отображается ожидание партнёра.

«Каталоги» доступны из пары. Шаблон применяется отдельной GET-формой и работает без JavaScript; после выбора нужно уточнить срок. Личный способ видит его владелец, отправленный снимок условия — партнёр. Для суши требуется размер, который не определяет цену.

Новые страницы проверены при ширине 320 px с длинным именем, без горизонтальной прокрутки и повторяющихся ID; шаблоны и сохранение правил проверены без JavaScript. См. [экономику и каталоги](economy-and-catalogs.md).

## Кухня и редактор

Кухня показывает собственные блюда или каталог действующего партнёра, фильтры по виду и две разные цены: примерные расходы на продукты в валюте карточки и стоимость заказа в сердечках. При минусе особые блюда недоступны, включая бесплатные особые; при нехватке свободного остатка у платного блюда показана причина. Сервер повторно проверяет правила при отправке, поэтому устаревшая страница не даёт права на заказ.

При выборе обычного блюда редактор устанавливает 0 сердечек. Фото можно просмотреть до сохранения; неподходящий формат, размер или ошибка чтения показаны рядом с полем. Серверная проверка и закрытая выдача сохраняются. Недоступное изображение в карточке заменяется подписью. Подробности: [кухня, желания и деньги](dishes-wishlist-money.md).

## Обязанности и виш-лист

Дела разделены на активные, ожидающие проверки, завершённые и все. Подтверждение ответа открывается отдельной нижней панелью; проверяющий партнёр проходит свою стадию. Возможная награда не показывается как новое обещание для уже завершённого дела. Подробнее: [дела и сердечки](hearts-and-duties.md).

Карточка желания использует фото слева и подробности справа, а при ширине до 360 px — одну колонку. Общий модуль фотографий обслуживает кухню и желания: предпросмотр, ошибки файла и недоступные фото в каталоге. Владелец может редактировать и архивировать свободное желание; партнёр просматривает его. Добавление, просмотр и архив работают без JavaScript. Подробнее: [кухня, желания и деньги](dishes-wishlist-money.md).

## Дополнительные формы и настройки

Профиль разделён на личные данные, валюту, реквизиты и состояние Telegram. Из «Моего пространства» доступны кухня, виш-лист, друзья, сердечки, пары и расписание текущей пары. Экономика видна только администратору. Состояние подключения показано текстом; секретные данные бота не выводятся.

Формы денег, свиданий и напоминаний используют общие поля валюты и многострочного текста, показывают ошибки рядом с полями и часовой пояс пары. Обычные поля сохраняются при ошибке; реквизиты не переносятся во временный ввод, в профиле снова видны ранее сохранённые данные. Отправка блокируется от повторного клика. Подтверждение обязательно и без JavaScript. Денежный запрос не выполняет банковский перевод, а напоминание не считается доставленным по факту сохранения.

Журнал сердечек показывает личный баланс, свободный остаток, резерв и историю. Для ручной благодарности или списания нужно ввести сумму, причину и подтвердить действие. Редактор экономики разделён на баланс, награды, благодарности, списания и штрафы; история версий остаётся доступной. Все дополнительные экраны используют нижнюю навигацию и мобильную типографику.

## Установка на телефон и отсутствие сети

Блок «Приложение на телефоне» убран из профиля по решению владельца от 12.10.2026; компонент `pwa-help` сохранён и не подключён. Его инструкции: Safari на iPhone/iPad → «Поделиться» → «На экран Домой»; Chrome на Android → меню установки или добавления на главный экран. Если браузер предлагает установку, появляется отдельная кнопка; запрос открывается только после нажатия. Отказ не считается установкой. В установленном приложении подсказка скрыта, верхний отступ учитывает safe-area.

При потере сети уже открытая страница показывает предупреждение и блокирует отправку обычных форм до восстановления подключения. Если сеть пропала во время отправки, проверьте результат после подключения: сервер мог принять запрос, а ответ не дошёл. Автоматической очереди и повторной отправки действий нет.

Переход на страницу без сети показывает публичный экран «Нет соединения» со статусом 503. Он не содержит личные просьбы, фото, реквизиты, балансы или сведения о входе. Service worker сохраняет только версионированные публичные иконки, offline-экран и файлы сборки с хешем; не перехватывает POST/PUT/PATCH/DELETE, личные JSON, фото и другие источники. Ответы с private/no-store, редиректы, неверный тип файла и ошибки не сохраняются. Кэш ограничен 50 файлами сборки, старые кэши приложения удаляются при обновлении.

Успешный выход возвращает серверную гостевую страницу. При возврате сохранённой браузером авторизованной страницы её содержимое скрыто и запрашивается заново, чтобы сервер повторно проверил сессию. PWA не создаёт долговременное хранилище личных данных. Обновление worker не перезагружает заполненную форму.

Проверены локальный Chromium, ширина 390 px, отключение/возврат сети и автоматические проверки кэша, форм и приватности. Реальные Safari iOS и Chrome Android, установка на устройстве и публичный HTTPS пока не проверены; эти приёмочные проверки остаются открытыми. Условия установки и различия браузеров: [MDN](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable).

Растровые оригиналы не изменены. Главная показывает фото партнёра, выделенный текст просьб, личный комплимент и приглашения к совместному выбору/жеребьёвке. Удержание карточки настроения открывает календарь; короткое нажатие сохраняет запрос настроения.

## Общее вращение колеса (0.23)
Рулетки фильмов и дел требуют двух согласий и двух открытых видимых страниц. Клиент отмечает присутствие раз в 1,5 секунды; отметка живёт 6 секунд в общем серверном кеше. Скрытая вкладка не продлевает присутствие. Оба согласия без присутствия не выбирают результат. WebSocket обновляет страницу при изменении состояния, а проверка присутствия также получает результат при пропущенном сигнале.

Сервер под блокировкой сохраняет один результат и `spin_started_at` с задержкой 5 секунд. Оба браузера используют общее время начала и 3-секундную анимацию; ответ показывается после вращения. Позднее открытие показывает то же завершённое колесо без повторного выбора. Если страница исчезнет непосредственно после последнего heartbeat, присутствие может сохраняться до 6 секунд; результат после старта не меняется. При отключении JavaScript автоматический совместный запуск не выполняется.

Нужен общий cache store между HTTP-процессами (например, настроенная database/Redis), не `array`. Конкурентные действия не создают вторую обязанность или новый результат.


## Общие темы, иконки и конструктор главной (0.24)

Закрытая админ-панель `/admin-panel` получила боковое меню: обзор/тесты, баланс, темы, иконки, конструктор главной и экономика. Доступ к новым разделам требует владельца панели и действующего второго пароля; роль администратора сама по себе его не заменяет. Настройки оформления общие для всех, включая гостевую страницу.

В «Темах» доступны облака и сердечки, весенний сад, летнее солнце, осень и зима. Можно добавить до 30 тем, изменить основные цвета, текст, карточки, два цвета и угол градиента, украшения или загрузить PNG/JPEG/WebP до 4 МБ и 4096×4096. Загруженное оформление доступно публично: используйте изображения, которыми можно делиться со всеми посетителями. «Смена темы» задаёт ручной выбор или сезонный режим: март–май, июнь–август, сентябрь–ноябрь и декабрь–февраль. Граница сезона определяется по Минску при открытии/обновлении страницы, без дополнительного scheduler. Для каждого сезона можно выбрать любую сохранённую тему.

Иконки темы задаются символами; раздел «Иконки» заменяет общие иллюстрации символами или картинками. Приоритет: общая замена → символ из темы → прежняя иллюстрация. Возврат к варианту «Из темы / обычная» снимает общую замену. Замены действуют в быстрых действиях и нижнем меню.

Конструктор управляет готовыми блоками главной и восемью быстрыми действиями. Можно перетаскивать за ручку или перемещать стрелками, отключать/возвращать элементы, менять подписи и цвет карточки, выбирать 1–4 колонки (на телефоне максимум две), добавлять текстовые карточки, всего до 20 блоков. Условия: всегда, есть/нет партнёра, машин больше нуля/нет машины, баланс положительный, есть дела/новая просьба. Ссылки и права остаются серверными; произвольные скрипты, HTML и выражения условий не выполняются. Служебные приглашения и вопросы настроения остаются видимыми вне редактируемой раскладки.

Предпросмотр использует данные текущего аккаунта, имеет переключатель ширины и пример условий; клик по блоку открывает его настройки. Он не выполняет действия и показывает заглушку для блока без данных. Настройки применяются ко всем только после подтверждения и сохранения. Конкурирующее сохранение устаревшей версии отклоняется с предложением обновить страницу.

Миграция `2026_10_12_122633_create_appearance_settings_table.php` добавляет единственную запись `appearance_settings`: первичный ID, номер ревизии, JSON тем/иконок/раскладки и даты. Сохранение блокирует запись, проверяет ревизию и атомарно добавляет `admin_audits`. Оформление хранится на отдельном диске `appearance_assets` в `storage/app/appearance`; каталог включают в резервирование и сохраняют между релизами. Новые файлы выдаются через ограниченный маршрут `appearance-assets`, личные фото из других дисков этим маршрутом недоступны. Перед применением в подтверждённом окружении сохраните базу и файлы, выполните штатные миграции и сборку по [операционным инструкциям](operations.md). Миграция в рабочей базе выполняется только после подтверждения окружения. Откат новой таблицы удаляет сохранённое оформление, поэтому перед откатом его сохраняют вместе с файлами.

## Тема «Тыквенный латте» и списки (0.25)

Тема по умолчанию — «Тыквенный латте»: кремовый фон, тыквенный акцент и украшение «Листья». Листья рисуются масками CSS и берут основной цвет темы; украшение доступно любой теме. Миграция `2026_10_12_135203_add_latte_theme_to_appearance_settings.php` добавляет тему в сохранённые настройки, делает её текущей, а при сезонном режиме назначает осени; свои темы не меняются. Откат убирает тему и возвращает «Облака и сердечки» и осеннюю тему сезона; правки самой темы «Тыквенный латте» при откате теряются. Прежние темы остаются в «Темах» и работают в новой раскладке.

Иллюстрации из растрового набора заменены линейными иконками компонента `icon`; `illustration` по-прежнему сначала применяет общую замену, затем символ темы. Плитка «Кто сделает?» получила собственную иконку. Шрифт остаётся Nunito.

Основные экраны собраны из строк с тонкими разделителями вместо карточек: `row` (строка списка), `group-label` (заголовок группы со счётчиком), `facts` (пары «поле — значение»), `steps` (этапы), `stat-row` (сводка), `settings-section` (раскрывающийся раздел). Карточки `card` остаются для обособленных блоков и форм. На внутренних страницах шапка показывает ссылку назад: по умолчанию на главную, экран может задать секции `back` и `back-label`.

- Главная: приветствие, строка партнёра, настроение и сердечки в две колонки, быстрые действия строками, дела списком.
- Просьбы: группы «Ждут ответа», «В работе», «Завершённые» в пределах страницы пагинации; метка «Ответить» видна только тому, от кого ждут ответ (`RequestProgress`). Принятая просьба открывает сразу карточку дела — сначала то дело, где нужен ответ зрителя; просьба без дел открывает свою страницу с ответом и условиями.
- Новая просьба: тема выбирается кнопками-переключателями (без JavaScript — обычные radio), быстрые сроки «Сегодня», «Завтра», «Через неделю» считаются на сервере в часовом поясе пары и появляются только при работающем JavaScript; кнопка отправки закреплена над нижним меню.
- Дела: группы «Просрочено», «Сегодня», «Ближайшие 7 дней», «Позже», затем по статусу (`DutyGroups`); границы дня — по часовому поясу дела. Карточка дела показывает этапы и сведения списком. Под заголовком сказано, чья это просьба или условие и кто выполняет. Проверяющий до отметки исполнителя видит заблокированную кнопку подтверждения с пояснением; исполнитель после отметки — заблокированную отметку и ожидание проверки. Отмена просьбы (общий компонент `request-cancellation`), сумма и реквизиты денежного дела доступны прямо в карточке; после отмены из карточки пользователь возвращается в неё же. Ссылки «К просьбе и условиям», «Все дела» и «Мои сердечки» убраны.
- Сердечки: крупный баланс, форма благодарности/списания в раскрывающемся разделе (открыт при ошибке), история со знаком суммы.
- Кухня и виш-лист: вкладки с подчёркиванием, блюда строками с фото, ценой и действием.
- Настроение: оценка выбирается значком, календарь текущего месяца показывает последнюю личную оценку каждого дня и сводку: частая оценка, число отмеченных и трудных дней (`MoodCalendar`). Вкладка партнёра показывает такой же календарь его оценок: дни — ссылки на записи выбранного дня со средним и графиком, стрелки листают месяцы. Карточка настроения на главной: одно нажатие спрашивает партнёра (с задержкой 350 мс на ожидание второго нажатия), двойное отправляет вопрос себе, удержание открывает календарь партнёра; подсказка доступна программам чтения с экрана.
- Профиль и страница пары: переходы списком, формы — в раскрывающихся разделах; все формы работают без JavaScript.

Проверяйте 360/390/430 px, длинные названия дел и блюд, пустые списки, прежние темы и отключённый JavaScript.

## Страница просьбы в раскладке дела (0.25.3)

Страница просьбы повторяет карточку дела: вид просьбы и статус в шапке, текст просьбы заголовком, строка о роли зрителя, шкала «создано → ответ → выполнение» (`RequestProgress::getStep`; у отклонённой и отменённой просьбы шаги не выделяются), сведения парами «поле — значение», пояснения блоками-подсказками, отмена — общим разделом `request-cancellation`. Страница остаётся отдельной, потому что у непринятой, отклонённой, отменённой и оценочной просьбы дела нет: здесь отвечают, предлагают и принимают условие. Принятая просьба из списка по-прежнему открывает сразу карточку дела.

## Быстрые действия и своё расписание (0.26)

К быстрым действиям главной добавлены «Напомнить» (форма нового напоминания пары) и «Комплименты» (страница `profile/compliments`); оба видны при наличии партнёра и настраиваются в конструкторе, где действий теперь десять. Миграция `2026_10_12_145211_add_reminder_and_compliment_tiles_to_appearance_settings.php` дописывает их в сохранённую раскладку, не меняя остальные; откат убирает их вместе с подписью и цветом. Редактор комплиментов убран из профиля и сохраняет результат на своей странице.

В «Моём расписании» участник задаёт время вопросов о настроении: поля времени с кнопкой «Добавить ещё время», пустое поле убирает вопрос, повторы объединяются, порядок — по возрастанию. Нужен хотя бы один и не больше восьми вариантов; включение и отключение расписания — отдельной кнопкой. Без JavaScript доступно одно дополнительное поле за сохранение. Колонка `couple_members.mood_schedule_times` добавлена миграцией `2026_10_12_145210_add_mood_schedule_times_to_couple_members.php`; её откат возвращает всем время по умолчанию. Добавление полей в комплиментах и расписании обслуживает один скрипт (`data-repeat-editor`).

Карточка настроения ждёт второе нажатие 500 мс; ответ сервера с причиной отказа показывается как есть, общий текст остаётся только для сбоя сети.

## Личная тема (0.27)

В профиле раздел «Тема оформления» предлагает темы из `AppearanceCatalog::PERSONAL_THEMES`: «Тыквенный латте», «Белая», «Любовная» и «Цветочная». Выбор хранится в `users.theme` и действует только для этого пользователя; пустое значение или тема, которой больше нет в настройках, означают общую тему из админ-панели (`AppearanceStore::currentId`). Гостевые страницы всегда используют общую тему. Тема меняет цвета, фон и украшение (`leaves`, `hearts`, `flowers` рисуются масками CSS, у белой темы украшений нет); раскладка главной, иконки-линии и блоки не меняются.

Миграции: `add_theme_to_users` добавляет колонку (откат возвращает всем общую тему), `add_personal_themes_to_appearance_settings` дописывает три новые темы в сохранённые настройки, не трогая существующие; её откат убирает эти темы вместе с правками. Новые темы можно править в админ-панели, как остальные; в списке украшений появились «Сердечки».

Комплимент партнёра выводится в приветствии главной вместо постоянной фразы и по-прежнему меняется каждые пять минут; без комплиментов остаётся фраза «Забота начинается с маленьких вещей». Блок раскладки «Комплимент» сохранён в конструкторе ради прежних настроек, но ничего не показывает; при отключённом блоке приветствия комплимент не виден.

## Магазин наград и памятные даты (0.28)

**Магазин наград** (`/rewards`, быстрое действие «Награды», ссылка в профиле). У каждого участника личный список наград: название, необязательные подробности и цена от 1 сердечка (таблица `rewards`, архив вместо удаления, версия и ключ операции как у остальных личных каталогов). Партнёр видит чужой магазин и кнопку «Купить»; при нехватке свободных сердечек кнопка заблокирована с пояснением. Покупка открывает форму новой просьбы с закреплёнными видом «Услуга» и ценой и создаёт обычную платную просьбу: согласие, резерв, проверка и списание идут по прежним правилам платных услуг, отдельного списания при покупке нет. Сервер при создании сверяет, что награда принадлежит получателю просьбы, не в архиве и цена совпадает с текущей (`RewardOffers`); иначе просьба не создаётся. Архивирование награды не трогает уже созданные просьбы. Миграция `add_rewards_tile_to_appearance_settings` дописывает быстрое действие в сохранённую раскладку.

**Памятные даты** (`/couples/{couple}/memorable-dates`, строка под партнёром на главной, раздел на странице пары). Список собирает `MemorableDates`: годовщины отношений и свадьбы считаются из дат пары, остальные хранятся в `memorable_dates` (до 50 на пару, ежегодные или разовые). Ближайшее наступление считается по часовому поясу пары; 29 февраля в невисокосный год отмечается 28-го; прошедшие разовые даты скрыты. Добавлять и удалять могут оба действующих участника, удаление требует подтверждения. Планировщик `care:process-due` в 09:00–09:30 по времени пары создаёт каждому участнику напоминание за три дня и в сам день (`CreateDateNotices`, журнал `memorable_date_notices` исключает повторы) и ставит его в общую очередь Telegram; текст экранируется, для дат пары добавляется номер годовщины.

Откат `create_rewards_table` удаляет магазины (просьбы и сердечки остаются), откат `create_memorable_dates_tables` — добавленные даты и журнал напоминаний. После обновления перезапустите `telegram-worker`, `telegram-poller` и `scheduler`.

## Серия и колесо свиданий (0.29)

**Серия** (`/couples/{couple}/streak`, строка под партнёром на главной, раздел на странице пары). `CoupleStreak` считает подряд идущие дни по часовому поясу пары, в которые оба действующих участника отметили настроение, либо день восстановлен. Пока сегодняшний день не закрыт, серия считается по вчерашний и не прерывается; статус показывает, кого ждём. Уровень огонька зависит от длины: искра с 1 дня, огонёк с 3, пламя с 7, костёр с 30, звёздное пламя со 100 (`CoupleStreak::LEVEL_DAYS`); компонент `flame` меняет цвет и свечение по уровню. Расчёт смотрит на последние 800 дней.

Прерванную серию можно восстановить, если пропуск примыкает к текущей серии, перед ним была серия и пропущенных дней не больше остатка восстановлений; восстанавливаются сразу все пропущенные дни, каждый тратит одно восстановление. На календарный месяц по времени пары даётся пять восстановлений на пару (`streak_restores`, один день восстанавливается один раз). Действие требует подтверждения и доступно обоим действующим участникам. Откат миграции `create_streak_restores_table` удаляет восстановленные дни, и державшиеся на них серии прервутся.

**Колесо свиданий** (`/couples/{couple}/date-ideas`, ссылка в форме свидания и на странице пары). Пара хранит до 12 идей (`date_ideas`). При двух и более идеях доступно колесо: сервер выбирает идею случайно, страница показывает трёхсекундное вращение прежнего компонента колеса и затем результат; при отключённой анимации результат виден сразу. Выбор хранится только во flash-сессии и не синхронизируется между партнёрами — это личный помощник, в отличие от общих колёс фильмов и дел. «Пригласить на это свидание» открывает форму свидания с подставленным названием; идея чужой пары не подставляется. Откат `create_date_ideas_table` удаляет идеи, отправленные приглашения остаются.
