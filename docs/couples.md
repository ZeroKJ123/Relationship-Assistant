# Пары и приглашения

После входа откройте «Мои пары» и пригласите партнёра. Дата начала обязательна и не может быть в будущем по часовому поясу пары. По умолчанию используется Europe/Minsk; принимаются зоны IANA. Дни вместе считаются по календарным датам этой зоны, после завершения счётчик останавливается.

Ссылка действует 7 суток и показывается автору один раз после выпуска. Новая ссылка отменяет предыдущую. Автор может отменить ссылку отдельно. Отмена и истечение срока оставляют ожидающую пару: можно выпустить приглашение снова или завершить её, чтобы принять чужое приглашение.

Получатель сначала входит или регистрируется, затем явно подтверждает принятие. После регистрации профиль показывает резервные коды и ссылку «Продолжить принятие приглашения». Нельзя принять свою ссылку, присоединиться третьим участником или иметь одновременно несколько ожидающих/активных пар. Повторное принятие тем же получателем не создаёт новую запись.

Оба участника равноправны. Любой может завершить пару после отдельного подтверждения. Это освобождает обоих для новой пары и отменяет ожидающие приглашения. История остаётся доступна прежним участникам, включая после создания новой пары. Новому партнёру и постороннему администратору она недоступна. Право `manage-system-settings` предназначено только администраторам и не открывает личные данные.

## Структура данных

| Таблица | Основные поля и ограничения |
| --- | --- |
| `couples` | `status`: pending/active/ended; `started_on`, IANA `timezone`, `currency`, `ended_at` |
| `couple_members` | Исторический `user_id`, `couple_id`, `slot`: first/second, `joined_at`, `ended_at`; уникальны пара+участник и пара+слот |
| `couple_members.active_user_id` | Уникальное nullable-ссылочное поле. Пока пара ожидает или активна, равно user_id; при завершении очищается, исторический user_id сохраняется |
| `couple_invitations` | Автор/пара, уникальный SHA-256 `token_hash`, pending/accepted/cancelled, срок, получатель и дата принятия |

В таблице приглашений нет исходного токена. Случайная ссылка содержит 64 символа; временный показ передаётся зашифрованной flash-сессией, привязанной к паре. Ответы не кешируются; Referrer-Policy: no-referrer ограничивает передачу ссылки через заголовок Referer. Логи содержат технические ID и этап операции без ссылки или личного текста.

Операции выполняются через Actions внутри транзакций. Сначала блокируются пользователи по возрастанию ID, затем пара и приглашение. Проверки повторяются под блокировкой. Ограничения базы поддерживают одну текущую пару на пользователя и два слота на пару. Если состав изменился во время подтверждения завершения, запрос предлагает обновить страницу и подтвердить актуальный состав снова.

## Миграция и откат

Миграция `2026_10_09_193842_create_couple_tables.php` добавляет три новые таблицы, не изменяя данные аккаунтов. В рабочую базу она автоматически не применялась. Перед применением используйте обычную процедуру выпуска с проверенной резервной копией. `down()` удаляет эти таблицы: схема возвращается назад, но история и приглашения будут потеряны. Для сохранения данных перед откатом нужна резервная копия и проверка её восстановления.

## Проверки

Обычные Pest-тесты используют SQLite в памяти. Отдельные интеграционные тесты запускаются в одноразовой MariaDB 11.4: две попытки разных гостей принять одну ссылку, один получатель с двумя ссылками и повторное принятие одним получателем. Они используют независимые PHP-процессы с общим стартовым барьером. Также проверяются ограничения самой базы. GitHub Actions выполняет обе группы проверок.

Для запуска и защиты тестовой базы см. [разработку](development.md). Telegram, сердечки и совместные дела остаются следующими этапами AF-плана.
