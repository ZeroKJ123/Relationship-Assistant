# Аккаунты и профиль

## Возможности

- `/register`: регистрация по имени, логину и паролю без обязательного email.
- `/login`: вход; `/logout`: выход только POST-запросом.
- `/profile`: собственный профиль и реквизиты; изменения сохраняются PATCH-запросом.
- `/recover`: восстановление пароля по одноразовому резервному коду.
- Вход через Telegram и привязка из профиля: одноразовая связка браузер–бот с двумя подтверждениями; [полная инструкция](telegram-and-scheduling.md).

Логин содержит 3–40 латинских букв, цифр или `_`; регистр не различается. Пароль — 12–128 символов, с буквами и цифрами. Для обращения доступны женский, мужской и нейтральный варианты; права от этого не зависят.

После регистрации восемь резервных кодов показываются один раз. Их нужно сохранить до следующего открытия страницы. В базе хранятся хеши кодов в зашифрованном поле; временный список в сессии тоже зашифрован. Использованный код удаляется атомарно под блокировкой аккаунта. После восстановления требуется новый вход, старые записи сессий этого пользователя удаляются, а middleware `auth.session` отклоняет сессии со старым хешем пароля.

Реквизиты зашифрованы и доступны сейчас только владельцу профиля. Партнёр видит снимок реквизитов только в принятом денежном запросе или условии. Поля администратора, пароля, реквизитов, резервных кодов и внутреннего пути фотографии не входят в обычную сериализацию пользователя. Клиент не может назначить себе административную роль.

## Подготовка подтверждённой среды

Миграции не запускались на рабочей MariaDB. Прежде чем пользоваться регистрацией, подтвердите окружение и сделайте резервную копию существующей базы. Затем в выбранной локальной Sail-среде:

```sh
./vendor/bin/sail artisan migrate
./vendor/bin/sail npm run build
```

На странице `/register` создайте аккаунт, сохраните коды, измените имя в профиле, выйдите и войдите снова. Для проверки восстановления используйте один сохранённый код на `/recover`; повторное использование должно быть отклонено.

`APP_KEY` обязателен для шифрования. Потеря ключа делает зашифрованные данные недоступными; секретный ключ храните отдельно от Git. Для обычной регистрации дополнительные настройки `.env` не нужны; настройки Telegram перечислены в его инструкции.

## Схема данных

| Таблица | Изменения |
| --- | --- |
| `users` | Nullable email/password; уникальный nullable login; gender, locale, currency, avatar_path, payment_details, recovery_codes; is_admin=false |
| `telegram_accounts` | Уникальные user_id и telegram_id; chat_id; timestamps; внешний ключ users с запретом удаления связанного аккаунта |

Существующие аккаунты сохраняются; новые поля у них могут быть пустыми. Новая регистрация явно записывает язык ru, валюту BYN и выбранное обращение. Валюта пары согласуется при её создании; автоматической конвертации нет. Вход через подтверждённый Telegram доступен после настройки бота.

Откат расширения users запрещается при аккаунтах без email или пароля: сначала восстановите резервную копию либо заполните настоящие значения. Откат удаляет новые колонки и таблицу идентификаторов; связанные данные нужно сохранить до отката. Пустой rollback не восстанавливает их содержимое.

## Проверки

Автоматические тесты используют только SQLite в памяти. Они проверяют регистрацию без email, хеширование пароля, ограничение попыток входа, смену сессии, CSRF, собственность профиля, шифрование, уникальность Telegram ID и одноразовый резервный код. Конкурентные завершения входа и регистрацию одной Telegram-личности проверяет `TelegramConcurrencyTest` в отдельной MariaDB.
